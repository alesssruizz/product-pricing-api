# CLAUDE.md

## Commands

```bash
make run        # ./gradlew bootRun → http://localhost:8080/pricing-service
make test       # ./gradlew test (also generates the JaCoCo report)
make fix-lint   # ./gradlew spotlessApply (google-java-format)
make lint       # checkstyleMain checkstyleTest spotbugsMain spotbugsTest
make all        # ./gradlew clean build

# Single test class / single method
./gradlew test --tests '*PriceCreatorTest'
./gradlew test --tests '*PricesPostControllerShould*createsThePrice'

# Run with the H2 console enabled (/pricing-service/h2-console)
./gradlew bootRun --args='--spring.profiles.active=dev'
```

Always run `make fix-lint` before `make lint`: formatting is owned by Spotless, never fixed by hand. Checkstyle runs with `maxWarnings 0`, so any warning fails the build. JaCoCo HTML report: `build/reports/jacoco/test/html/index.html`.

## Build layout

There is a **single Gradle module** with custom source sets (no `src/main`):

- `apps/main` + `pricing/main` → main source set; `apps/main/resources` + `pricing/main/resources` share one classpath root.
- `apps/test` + `pricing/test` → test source set.

Consequences: a resource can exist only once across both trees (e.g. there is one `logback.xml`, in `apps/main/resources`; a second one breaks `processResources`), and `pricing` code can see `apps` classes at compile time — keep the dependency direction `apps → pricing` by convention.

## Architecture

Hexagonal architecture with lightweight CQRS over in-memory buses.

- `pricing/main/com/inditex/pricing/prices` — the `prices` bounded context: `domain` (aggregate `Price`, value objects, `PriceRepository`/`PriceReferences` ports, `policy/`, `exception/`), `application` (one package per use case), `infrastructure/persistence/jpa` (adapters).
- `pricing/main/com/inditex/pricing/{brands,products}` — read-only contexts: domain model (`Brand`/`Product`, own `BrandId`/`ProductId`) and JPA entities. No use cases and no repository ports yet; brands and products cannot be created through the API.
- `pricing/main/com/inditex/pricing/shared` — shared kernel: base value objects, `Identifier`, `DomainError`, bus interfaces and their in-memory implementations. **Must not import from any context.**
- `apps/main/com/inditex/apps/pricing` — Spring Boot entry point, config (API versioning, OpenAPI), REST controllers and error handling.

Context boundaries: the `prices` domain and application reference brands and products **only by id**, using their own `BrandId`/`ProductId` value objects, and never import `brands`/`products`. The only allowed cross-context imports are infrastructure → infrastructure (`PriceJpaEntity` relations, `JpaPriceReferences`). Packages are singular (`exception`, `policy`).

### Wiring

- Beans are not registered with Spring stereotypes in the core: classes use the project's own `com.inditex.pricing.shared.domain.Service` annotation, picked up by an `includeFilters` `@ComponentScan` in `ProductPricingApiApplication`.
- Command/query handlers are indexed automatically by the generic type they implement (`QueryHandlersInformation` / `CommandHandlersInformation`); two handlers for the same type fail at startup.
- A use case package contains the `Command`/`Query` record, its `*Handler`, and the application service that does the work (e.g. `create/`: `CreatePriceCommand`, `CreatePriceCommandHandler`, `PriceCreator`).

### HTTP layer

- One controller per use case under `controller/prices/v1/{get,post,put,patch,delete}`. Controllers extend `ApiController` and talk to the core only through `ask(query)` / `dispatch(command)`.
- Error mapping is per controller: override `errorMapping()` (`DomainError` subclass → `HttpStatus`). `ApiExceptionHandler` unwraps bus wrapper exceptions, looks up the **exact class** (no subclass matching) and returns a `ProblemDetail` with an `errorCode` property. Anything unmapped becomes a logged `500`.
- Adding a domain error: extend `DomainError` with a stable snake_case `errorCode`, add it to every relevant controller's `errorMapping()`, and document it in that controller's `@ApiResponses`. `Map.of` accepts at most 10 pairs — switch to `Map.ofEntries` beyond that.
- Versioning: mappings declare `version = "v1"`; `WebMvcConfiguration` adds the `/api/{version}` prefix. The servlet context path is `/pricing-service`, but MockMvc tests call `/api/v1/...` directly.

### Domain model

- `Price.create` / `Price.update` / `Price.delete` build the aggregate from value objects and record domain events; the public raw-type constructor is the rehydration path used by `PriceJpaAdapter.toDomain`. Value objects and `ensureValidDateRange()` validate in both paths.
- Accessors are generated by Lombok in fluent style (`lombok.config`: `lombok.accessors.fluent = true`), so they read `price.id()`, `price.priceAmount()`.
- Aggregates are entities: equality is by id only (`@EqualsAndHashCode(callSuper = false, onlyExplicitlyIncluded = true)` + `@EqualsAndHashCode.Include` on the id). Domain events keep full-field equality.
- Price ids are UUIDs **supplied by the client** (mandatory in the `POST` body). `Identifier` validates the canonical 36-char form and throws the generic `InvalidUUID` (`invalid_uuid`).

### Integrity policies

- Business rules checked before saving a price (create, update, patch) live in `prices/domain/policy/` and implement `PricePolicy` (`void ensure(Price)` throwing a `DomainError`, plus `int order()`).
- `PriceIntegrityChecker` receives every `PricePolicy` bean as a `List`, sorts it by `order()` and runs them, stopping at the first failure. To add a rule, create a new `PricePolicy` class annotated with the project's `@Service`; do not touch the checker or the use cases.
- Order defines which error the client gets when several rules fail: `PriceReferencesPolicy` (10, `invalid_reference`) runs before `PriceConflictPolicy` (20, `price_already_exists`). Leave gaps when choosing a new order value.

### Persistence

- The port exposes `create(Price)` and `update(Price)`, never a generic `save`. `PriceCreator` checks `existsById` first (→ `409 price_id_already_exists`); the primary key is only a safety net.
- `PriceJpaEntity` is hand-written (no Lombok) and implements `Persistable<UUID>`. `forCreate` / `forUpdate` set a `@Transient` flag so Spring Data `save()` issues `persist` (INSERT only) for creates and `merge` for updates. Do not replace this with `@PostLoad`/`@PostPersist` callbacks: the adapter always builds a fresh entity from the domain, so callbacks would never fire. `PriceJpaAdapterTest` guards the flag.
- `PriceJpaEntity` maps brand and product as `@ManyToOne(fetch = LAZY, optional = false)` to `BrandJpaEntity` / `ProductJpaEntity` (hand-written, `@Immutable`, not `final` so Hibernate can proxy them). The adapter builds references with `getReferenceById` (no SELECT). The entity exposes only `getBrandId()` / `getProductId()`, which read the id from the lazy proxy without initializing it — `PriceJpaEntityLazyRelationsShould` guards this. Do not add `getBrand()` / `getProduct()`.
- `prices.created_at` / `updated_at` are persistence-only audit columns (`TIMESTAMP WITH TIME ZONE`, `Instant`). They are not part of the `Price` domain, `PriceResponse` or the events. Hibernate fills them (`@CreationTimestamp`, `@UpdateTimestamp`). `created_at` is `updatable = false` because `forUpdate` builds a fresh entity whose audit fields are null and is merged. As a result, any PUT/PATCH, including a no-op one, refreshes `updated_at`. The entity has getters only. Seed rows have fixed past values in `data.sql`. `PriceAuditTimestampsShould` guards this behavior (flush + clear before reading).
- No native SQL: reference checks use Spring Data `existsById` (`BrandJpaRepository` / `ProductJpaRepository`, narrow `Repository<E, Long>` interfaces), conflicts use the derived query `existsByBrand_IdAndProduct_IdAndPriorityAndStartDateAndIdNot`, and `findApplicablePrice` is JPQL (`p.brand.id`, `LIMIT 1`).
- The schema is owned by `pricing/main/resources/database/schema.sql` + `data.sql` with `ddl-auto=validate`; schema changes go in those files. Seed price ids are `00000000-0000-0000-0000-00000000000{1..4}`; brand and product ids are `Long`.

## Tests

- Unit tests (`pricing/test`, suffix `*Test`): domain and use cases, Mockito, `@Nested` per scenario, no Spring.
- Acceptance tests (`apps/test`, suffix `*Should`): extend `ProductPricingApiApplicationTests` (`@SpringBootTest` + MockMvc). Each Spring context gets its own in-memory H2 database (`jdbc:h2:mem:${random.uuid}`); write tests are `@Transactional` and roll back. `assertResponse` compares JSON leniently (array order ignored).

## Lint gotchas

- Checkstyle `NeedBraces`: single-line `if` without braces is rejected.
- Checkstyle `RightCurlyAlone`: an empty `{}` body is rejected after google-java-format collapses it — put a comment inside.
- SpotBugs exclusions live in `config/spotbugs/exclude-filter.xml` (e.g. `CT_CONSTRUCTOR_THROW` for value objects that validate in the constructor).
